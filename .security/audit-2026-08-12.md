# Security Audit Report

**Date:** 2026-08-12 | **Auditor:** Codex multi-agent review | **Repo:** ashlrai/ashlr-hub (TypeScript/Node.js)

## Executive Summary

The composed candidate substantially improves proposal identity, default-deny effect policy, and local-model shadow evaluation, but it is not safe for unattended or resident production. The maximum defensible authority is an owner-invoked, one-shot proposal laboratory with non-winning local shadow evaluation. Consequential effects, paid/cloud autonomy, resident activation, self-merge, and deployment remain blocked.

**Risk Rating:** Critical for unattended production; Medium for the scoped proposal-only laboratory
**Findings:** 6 Critical, 5 High, 5 Medium, 3 Informational

## Findings

### CRITICAL

1. **No authenticated effect capability exists.** `src/core/inbox/review-policy.ts` deliberately sets `HUMAN_EFFECT_CAPABILITY_AVAILABLE = false`; apply, merge, remote handoff, and auto-merge are unavailable. This is safe quarantine, not full functionality.
2. **No resident lifecycle authority exists.** Activation trust roots are empty, live conductor authorization is false, and `service-install-authority.ts` denies install/reinstall/repair/restart.
3. **OS confinement is optional and can fall back.** External Claude/Codex use permission-bypass flags while absent confinement defaults off; macOS vendor credential homes remain accessible and Linux read-only binds `/`.
4. **Verification is not an independent security principal.** Repository scripts execute with inherited host environment and mutable dependency paths; the execution-authority capsule remains observation-only.
5. **Release/install/rollback are observation-only.** Runtime launch admission explicitly denies deploy/install/launch/start/rollback and has no effect consumer or replay-safe transaction.
6. **The candidate is not deployed.** Protected master, package publication, installed immutable release, and resident runtime all have different identities; the installed 3.1.0 daemon is stopped.

### HIGH

1. Concurrent workers lack atomic per-provider-call spend reservations; tick-level reservation does not prevent all workers from passing a mutable budget check before settlement.
2. Detached or new-session descendants can escape kill ownership.
3. Same-user local HMACs provide tamper evidence, not independent human or release authority.
4. Ollama digest verification authenticates loopback inventory metadata, not model-serving bytes; Nemotron must remain non-winning shadow only.
5. Self-target detection fails open on package-read or parse uncertainty and protects only a selected file list.

### MEDIUM

1. Dispatch-production evidence is degraded by four invalid rows, withholding learning/outcome authority.
2. Semgrep reported 30 audit findings, primarily unchanged dynamic-regex and shell patterns; every changed-file intersection requires explicit triage before release.
3. Gitleaks reported 77 synthetic canary/fixture/domain-string hits; exclusions must remain narrow and documented rather than suppressing whole test trees.
4. The composed human-effect and Nemotron branches had no prior hosted exact-head checks; the combined PR must supply authoritative merge-ref evidence.
5. The local Semgrep report had analysis timeouts on changed security-sensitive files and neither local scanner report was bound to an exact Git SHA. Manual hunk review found no introduced sink, but only exact-head hosted security evidence can clear merge.

### LOW / INFORMATIONAL

1. `npm audit` reports zero known dependency vulnerabilities for the installed lockfile closure.
2. Focused combined authority/model validation passed 234 tests plus typecheck.
3. Protected master is red from an expired test clock; the integrated three-line M380 fixture repair preserves production policy.

## Recommendations

### Immediate (0-48h)

- Merge only after exact protected checks on this combined source and keep authority proposal-only.
- Do not start, install, publish, tag, or activate a resident artifact.
- Decide explicitly whether disabling all normal human approval is the intended quarantine release.

### Short-term (1-2 weeks)

- Implement a hardware/OS-backed, one-use human effect capability validated under the final sink lock.
- Require OS confinement with `onUnsupported:'fail'`, no ambient credentials, and controlled egress for autonomous execution.
- Add crash-safe hierarchical per-call reservations and complete child-process ownership.

### Medium-term (1-3 months)

- Build an independent immutable verifier broker.
- Implement the native signed, journaled, replay-safe install/start/rollback consumer with canary evidence.
- Add externally rooted release and human trust principals; retain model output as non-authoritative evidence.
