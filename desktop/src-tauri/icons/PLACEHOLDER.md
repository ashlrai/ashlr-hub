# Native icon sources and generation

`icon.svg` is the Phantom app icon source. It places our existing blue ghost on the existing rounded-square native canvas; the mark geometry, gradient and eye colors are preserved. The first-party mark comes from `ashlrai/phantom-secrets` commit `bf4b06edd12bbac772d8b56b6001778bb0f910a6`, `apps/web/public/favicon.svg`, SHA-256 `8cfd1f86237a521ee43e74394712b489ff0cc2adfe70dcf8ac500056314c4269`. Its MIT notice is preserved in [`desktop/PHANTOM-ICON-LICENSE.txt`](../../PHANTOM-ICON-LICENSE.txt).

The following generated files must exist before `cargo tauri build` bundles the app:

| File | Size | Used by |
|------|------|---------|
| `32x32.png` | 32×32 px | Bundle icon |
| `128x128.png` | 128×128 px | Bundle icon |
| `128x128@2x.png` | 256×256 px | Retina bundle icon |
| `icon.icns` | Multiple sizes | macOS app |
| `icon.ico` | Multiple sizes | Windows executable and installer |

These five files are generated build inputs, not checked-in source files. Local/global Git ignores may hide them; generate them from the tracked SVG whenever it changes, and do not force-add generated output. The existing `tray.png` is a separately tracked monochrome template icon selected by `app.trayIcon.iconPath`; it is not generated by the app-icon command. Its template behavior allows macOS to invert it for dark mode.

## Generate

With the repository's existing Tauri CLI installed:

```sh
cd desktop
npm run icons
```

Or run `./generate-icons.sh` from this directory. The existing generator also emits Windows Store, iOS and Android images. Only the five files above are listed in the bundle configuration. No ImageMagick or librsvg installation is needed by the installed Tauri SVG pipeline.

For an isolated reproduction, `cargo tauri icon src-tauri/icons/icon.svg --output /absolute/private/output` writes the same generated assets outside the checkout. These assets do not rename the native bundle, signing identity or package.
