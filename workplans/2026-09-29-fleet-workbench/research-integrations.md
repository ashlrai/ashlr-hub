# Fleet provider and codebase-map research

Verified 2026-09-29 against installed model metadata and primary provider/repository sources. No provider credential values were inspected or retained, paid provisioning performed, external agents dispatched, or third-party code copied during this workstream.

## Providers and subscriptions

- **GPT-6.1 Sol** is the exact model identifier `gpt-6.1-sol`, not “Soul.” The installed Codex model cache advertises it as visible with a 272,000 default provider window, 872,000 maximum, and 95% effective context. Hub uses those account-specific catalog facts when available; the fallback was updated from this installed evidence. The API product documents a different 1.05M window, so it must not replace Codex CLI context evidence. [Official model documentation](https://developers.openai.com/api/docs/models/gpt-6.1-sol).
- **Devin** has official v3 organization and enterprise REST APIs with service-user RBAC and personal access tokens. Session impersonation requires its explicit organization permission. Existing Hub cloud/CLI adapters should retain this distinction from subscription-native Claude/Codex/Grok account seats; one configured Devin connection is not proof of arbitrarily many authenticated Devin identities. [API overview](https://docs.devin.ai/api-reference/overview).
- **Claude Code subscription access** remains a supported existing lane: the official article explicitly says the June 15 change for Agent SDK, `claude -p`, and third-party subscription usage is paused. Do not interpret the historical text retained beneath that notice as the current policy. Keep subscription launcher isolation and API billing as separate account facts. [Official support article](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan).
- **Grok Bot** is a persistent cloud computer/browser/terminal product with linked account eligibility. Hub’s native Grok CLI integration does not itself prove Grok Bot dispatch capability. Public bot dispatch API authorization was not established here; xAI model API access is a separate integration. [Bot overview](https://docs.x.ai/grok-bot/overview), [eligibility and setup](https://docs.x.ai/grok-bot/get-started).
- **Qwen3.8-27B** is a real official Apache-2.0 model with tool use and local deployment instructions. The repository already prefers an Ollama `qwen3.8:27b-ctx64k` variant; that runtime’s Modelfile/allocated context, not the model card’s maximum, governs the seat’s usable context. [Official model card](https://huggingface.co/Qwen/Qwen3.8-27B).

## Meta Muse verified contracts

Meta’s public preview exposes OpenAI-compatible Chat Completions at `https://api.meta.ai/v1`, with the documented model `muse-spark-1.3`. Its quickstart passes `MODEL_API_KEY` explicitly as the SDK key; an arbitrary environment variable is not automatically discovered by the OpenAI SDK. Responses API is also documented, particularly for reasoning replay. The model documentation states a 1,048,576 context and 131,072 output limit. Hub should opt in through its existing config-only engine registry, retaining explicit API credentials/billing and capabilities. [Meta launch](https://ai.meta.com/blog/introducing-muse-spark-meta-model-api/), [Chat Completions cookbook](https://dev.meta.ai/docs/cookbook/quickstart-chat-completions), [quickstart](https://dev.meta.ai/docs/quickstart).

Muse Code additionally documents browser login and API-key authentication, `META_API_KEY` for CI, `muse exec --json "<prompt>"` JSONL output, `--session-id <uuid>` continuation, and `muse export --session UUID --out run.json`. Exit zero means the turn completed, not that its work was validated. Headless configuration offers `--model`, `--reasoning-effort`, `--workspace`, and `--max-model-steps`. The stable `muse serve`/`muse schema` contract and TypeScript SDK are preferable to inventing an ACP contract. Subscription entitlement across arbitrary third-party launchers was not established. [Muse Code](https://dev.meta.ai/docs/muse-code), [headless extension contract](https://dev.meta.ai/docs/muse-code/extending), [configuration](https://dev.meta.ai/docs/muse-code/configuration).

## Dots versus API agents

OpenAI Dots are documented always-on GPT-6 Astra agents with their own cloud computers, gradually enabled for eligible subscription/workspace plans. They can create Codex local/cloud tasks through a connected computer; local access is optional and initially off. A public external Dots dispatch API was not verified. Expose an honest external handoff/discovery status until an official contract exists. [Getting started](https://help.openai.com/en/articles/20001530-getting-started-with-your-dot), [permissions and privacy](https://help.openai.com/en/articles/20001529-dots-privacy-security-and-safety-faqs).

The separately documented managed **Agents API** supports sessions, compaction, orchestration and recovery. It is API billed, requires application API-key permissions, and uses `OpenAI-Beta: agents=v1` with `POST /v1/agents/sessions`. It supports no environment, OpenAI-hosted, and self-hosted environments. This is a possible future adapter, not a claim that Dots subscription usage is available through that API. [Overview](https://developers.openai.com/api/docs/guides/agents-api/overview), [quickstart](https://developers.openai.com/api/docs/guides/agents-api/quickstart), [MCP tool boundary](https://developers.openai.com/api/docs/guides/agents-api/tools/mcp).

## Graphify research and implemented local map

Reviewed Graphify `v8` tree `1cd9a36c0c57a661d2d2234bc3207e887e1ba104`. Its architecture separates deterministic syntax extraction from optional semantic inference; graph edges retain provenance and confidence, and query/path/explain tools scope context to relevant neighborhoods. Incremental extraction and explicit root boundaries are useful patterns. Its package metadata declares Apache-2.0; NOTICE explains that earlier MIT portions remain under their original terms. The retained LICENSE-MIT is not a blanket dual-license permission for all current code. No Graphify code or dependencies were incorporated. [Repository](https://github.com/Graphify-Labs/graphify), [architecture](https://github.com/Graphify-Labs/graphify/blob/v8/ARCHITECTURE.md), [package metadata](https://github.com/Graphify-Labs/graphify/blob/v8/pyproject.toml), [NOTICE](https://github.com/Graphify-Labs/graphify/blob/v8/NOTICE).

Hub already has bounded wiki scanning/facts/citations, a regex repo map and an enrolled knowledge import graph. This release reuses `scanRepo` + `extractFacts` to provide `GET /api/verse/wiki/repo/<key>/graph` and a Wiki “Module map” surface. Search/select/dependency navigation uses keyboard-accessible HTML buttons over an SVG overview; details show read-file and export citations. The API returns metadata only, never source text. Existing enrollment/read authentication remains in place; phone gateway policy continues to deny wiki reads. Scanner bounds remain 6,000 listed files, 1,600 reads, 16MiB aggregate and 256KiB per file. Displayed modules inherit the existing 48-module fact bound; the UI explicitly reports unread/omitted files and listing truncation. Directory grouping and regex-resolved import links are labeled inferred, with incomplete language/runtime coverage. Steering exclusions are checked before cache reuse. Failed/depth-limited directory listings are explicitly incomplete; source reads reject symlinks in every path component, verify realpath confinement, use nofollow opening and fixed read allocation. No model or external index service is involved.

## OmniRoute research and routing/context opportunities

Reviewed OmniRoute `release/v3.8.52` tree `a1a2dce1a64a4b123f80ec899fc88bb2aa34d1a4`, MIT licensed. Its architecture covers routing scores, quota resets, prompt-cache affinity, durable circuit states, anti-herd coordination, request deduplication and observability. Hub’s declarative engine registry, pool policy/shared capacity keys and connection monitor already provide suitable homes for these ideas. Rank only candidates that have passed Hub’s capability, credential, authority, budget and capacity checks. OmniRoute documents category-filter fail-open behavior and a cheapest budget fallback that can exceed the cap; those defaults should not be transplanted into Hub’s hard-policy eligibility. [Architecture](https://github.com/diegosouzapw/OmniRoute/blob/release/v3.8.52/docs/architecture/ARCHITECTURE.md), [auto routing](https://github.com/diegosouzapw/OmniRoute/blob/release/v3.8.52/docs/routing/AUTO-COMBO.md), [score implementation](https://github.com/diegosouzapw/OmniRoute/blob/release/v3.8.52/open-sse/services/autoCombo/scoring.ts), [license](https://github.com/diegosouzapw/OmniRoute/blob/release/v3.8.52/LICENSE).

Its compression validator checks retained material against original input, with fallback/error reporting rather than treating compressed text as automatically equivalent. Related tests cover inflation, file contents, raw output, severity, and cache controls. For model/company-agnostic ash lr-plugin, Locus and Phantom context efficiency, preserve raw local evidence and citations, scope retrieval first, then validate any lossy reduction. Measure task success and tokens together; source presence or a compression ratio is not validated savings. Hub’s wiki Ask retrieval already scopes private facts using a 9,000-character budget, and repo-map prioritizes signatures/imports within a token budget. These are practical reusable foundations. [Compression validator](https://github.com/diegosouzapw/OmniRoute/blob/release/v3.8.52/open-sse/services/compression/validation.ts).

## Catalog scalability changes and limits

Account catalogs no longer truncate at 256 models; they retain file-size limits, validation, deduplication and bounded cache entries. Local seats retain every accepted `/api/tags` name within a 1MiB response bound, with concurrency eight and a two-second capability-inspection budget per refresh. Completed metadata is cached for 30 seconds; missing rows lead before oldest stale rows so a slow early model cannot starve later tags. All pending names remain visible but unavailable for dispatch, with explicit inspected/pending counts and a refresh instruction. No long-running background sweep is started. Oversized tag responses are refused rather than represented as a complete truncated roster.

The detailed Usage report also retains every accepted Ollama/LM Studio name and resident row within a 1MiB metadata bound. Its existing expensive 48-show observation budget remains, now explicitly reported as attempted/pending detail inspection with unsampled capabilities unknown. Provider quotas, hardware and explicit resource/concurrency limits remain meaningful capacity controls even though there is no arbitrary account or selectable-catalog count cap.
