# Work with me / Work for me

The workbench has two primary jobs: interactive engineering with the user and delegated engineering for the user. Both use the existing accounts, projects, sessions and operational controls.

## Delivery plan

1. Make the two workspaces visible in the shell, preserve current destinations, deep links, keyboard commands, mounted sessions and drafts. Restore the saved workspace on launch. Navigation does not dispatch work or change permission mode.
2. Keep agent creation focused on repository, seat and task. Move optional planning, CI and spending options into a disclosure. Remove the arbitrary six-seat fan-out limit; every selected seat still gets an isolated workspace and its own normal dispatch admission.
3. Replace fixed change-volume ceilings with reviewed, operator-signed limits. An optional signed policy marker distinguishes the new policy from older grants, whose effective scope must remain unchanged. Preserve authentication, account isolation, protected paths, spending authority, Stop, revocation, signed scope, verification and rollback.
4. Make evaluation usage explicit: reported token counts, including zero, differ from absent or invalid usage. Compare bounded receipts only when task, model, runtime, configuration and cache conditions match. No comparison invokes a model.
5. Explain both workspaces and the signed-limit policy in the product documentation and public site. Prepare a new release; do not reuse any 3.17.2 validation or publication receipt for the new artifact.
6. Run focused regressions, type checks, lint, documentation/first-paint checks and the complete release gate. Review the exact candidate, publish verified artifacts, deploy the exact source and verify public/mobile and installed behavior.

## Acceptance

- Switching workspaces cannot start, stop or grant an agent authority. Existing running sessions and drafts survive switches.
- Existing grants retain their canonical bytes and effective scope. Larger or uncapped volume requires an explicit reviewed edit and a new signature from the compatible custody helper.
- Optional agent settings retain their current submission semantics and defaults. Multiple seats retain workspace isolation; failed starts remain visible.
- Missing usage never becomes measured zero or a savings claim. Incompatible evaluation receipts cannot produce a paired efficiency claim.
- Production means a verified deployment, public release/download or registry consumer at its exact layer. A published workbench is not proof of resident activation or provider qualification.

## Operator gates

npm approval, Mac unlock, custody helper installation/Touch ID signing, resident startup and physical-phone authentication require the operator. Meta Muse Code subscription qualification, external Dot dispatch and the Claude credential broker remain separate implementation/qualification work until their real contracts are supported.

## Reviewed performance allowance

The new primary workspace controls measured 360,612 bytes of desktop critical JavaScript. Reusing existing shell grouping and navigation reduced this to 360,511 bytes. That is 63 bytes beyond the prior 352 KiB release allowance. The desktop release check moves to the next whole KiB (353 KiB); the phone allowance stays 250 KiB, with 255,145 bytes measured. Long explanatory tooltips and immediate navigation stay intact. This measured artifact check is separate from runtime spending or task admission.

## Dynamic budget correction

An ordinarily exhausted positive metered-dollar allowance must not park resident agents whose actual admitted execution is proven zero-meteredness. Preserve explicit zero-as-stop, signed spending scope, account reserves, unknown-cost refusals and unresolved accounting holds. Recheck final routing and fallbacks, use normal run token capacity for free production, and keep normal maintenance cadence. No generated evaluation or benchmark is a prerequisite for normal work.

## Managed API and companion research

Add a supported read-only managed OpenAI Agents inventory CLI with fixed official TLS transport, metadata projections, bounded requests and host-held authentication. Keep API access separate from subscription seats. Research Dots companion/plugin-event connections and durable orchestration against official documentation and actual Hub seams; do not report an unimplemented event or execution adapter as connected.

## Operator capacity consistency

Remove arbitrary upper clamps from existing daemon capacity preferences while preserving defaults, positive safe-integer validation, actual resource admission, signed scope and explicit Stop. UI preferences must match the runtime instead of offering values the daemon silently reduces.
