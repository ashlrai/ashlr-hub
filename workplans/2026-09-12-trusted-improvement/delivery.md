# Retained preparation evidence handoff

The implemented CLI/SDK path is retained captures → reproducible calibration →
captured candidate comparison. See the canonical
[operation guide](../../docs/ASHLR-UNIVERSE.md#calibrate-and-compare-retained-preparation-evidence)
and [verification record](../../artifacts/preparation-calibration-verification.md).

It provides fifteen-region process and blob deltas, whole-artifact scope checks,
historical workload identity joins, strict input handling and no automatic retry.
It does not install an acceptance score, select winners or deliver code.

Remaining work toward the actual self-improvement loop:

1. Package trusted scoring plumbing with candidate-linked during-call mutation
   qualification, using the same owned evaluator activity and original deadline.
2. Retain three actual successful baseline captures of the final workload bytes.
   The real global KILL switch remains active; this handoff does not override it.
3. Pin that baseline in the installed score, evaluate an actual candidate, and
   join passing evidence into the existing campaign archive and delivery path.
4. Prove continued operation, storage lifecycle and live acceptance separately.

No GitHub Actions, remote push, npm publication, provider consumption, account
allocation changes or resident service activation occurred in this increment.
