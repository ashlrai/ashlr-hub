Measured, not estimated

One bug was costing 23,500 tokens a turn.

Claude Code appends a token counter to every request, and it changes each turn. Verse was folding that into the system prompt, ahead of the whole conversation, so the prompt prefix changed on every request and llama.cpp could reuse none of its cache. Every turn reprocessed the entire context. The work was correct the whole time. It was just slow.

Same tasks, same hardware, same model, before and after the fix.

Worth saying plainly, because most tools will not: on one GPU, parallelism buys throughput, not speed. Four agents finish about 1.1× more work per minute than one at a time. The large win above was the cache fix, and it helps a single agent just as much.

How local actually works

Discovery and dispatch are different problems.

Most local setups collapse them, then wonder why the model picker goes empty. Keeping them apart is what lets dispatch move onto the fast runtime without losing the seat list.

Why discovery stays put

Which models you have, their context window, and whether they can call tools at all come from Ollama. A model without tool support cannot drive an agent session, so Verse hides it rather than letting you pick something that fails on the first turn.

Why dispatch is opt-in

The proxy is a separate listener from llama-server. Inferring the lane from “llama-server is up” would point every local seat at a closed port. So it is a switch, and an unset or malformed value falls back to the lane that already works.

Autonomy

Out of the loop, not out of control.

Verse can run agents with nobody watching. That is only worth having if the blast radius is something you set deliberately, so the limits are part of the product rather than a setting you hope someone remembered.

Enrollment scope
An autonomous agent can only touch repositories you enrolled. Adding a folder to a project does not silently widen what the unattended lane can reach.
Proposals, not pushes
Unattended work lands as a proposal you approve. Anything that leaves the machine, a branch, a pull request, a message, waits for that click and tells you what it will do first.
Usage ceilings
Cap what the autonomous lane may spend as a share of each subscription. Local seats cost nothing, so a fleet keeps working past the paid ceiling.
Claim checking
A turn that reports a fix while changing no file is flagged rather than marked done. The classifier judges only what the message claims; whether the tree moved is read from the tree.
Kill switch
One file on disk stops every autonomous effect immediately. It is checked on the effect itself, not on the scheduler, so a loop already in flight cannot outrun it.

Get started

Three steps to a working fleet.

Install and open the console

Same command on all three platforms. It finds the agent CLIs you already have.

npm i -g @ashlr/hub
ashlr verse

Bring up the local runtime

Starts llama-server with batching slots and the normalising proxy in front of it.

ashlr local-runtime start --slots 4

Put local turns on the fast lane

Opt in, because the fallback should be the lane that already works.

export ASHLR_VERSE_LOCAL_DISPATCH=llama-server

What you need

Node.js 22 or newer, and Git. Ollama for model discovery. Whichever agent CLIs you already use, signed in as you normally would. For a 27B model at four-bit, roughly 48 GB of memory to hold the weights resident.

Verse never asks for your credentials. It drives each CLI with its own pinned profile, and the console itself is loopback-only: it prints a token at startup and will not answer a request that does not carry it.
